### 部署踩坑 / 红线（GitHub Actions 跑 hexo deploy 必记）
1. **pnpm 10 默认拦截依赖构建脚本**：`pnpm install --frozen-lockfile` 因 `hexo-util` 的 postinstall 被拦直接 exit 1（ERR_PNPM_IGNORED_BUILDS）。修复：`pnpm-workspace.yaml` 顶层写 `onlyBuiltDependencies: [hexo-util]`（注意字段名是 onlyBuiltDependencies，不是旧 RC 的 allowBuilds）。`package.json` 里的 `pnpm.onlyBuiltDependencies` 在 workspace 下被忽略，必须以 workspace yaml 为准。
2. **git 身份**：hexo-deployer-git 在新建的 `.deploy_git` 里 commit，读不到仓库级 config。必须在 workflow 注入 `GIT_AUTHOR_NAME/EMAIL`、`GIT_COMMITTER_NAME/EMAIL` 环境变量（或 git config --global）。否则 `fatal: empty ident name`。
3. **deploy key 不持久**：`actions/checkout` 的 `ssh-key` 只在 checkout 步骤有效，其 Post Run 会卸掉钥匙；`hexo deploy` 推 gh-pages 时 `Permission denied (publickey)`。修复：在 deploy 步骤里 `printf` 出私钥到 `~/.ssh/deploy_key` + `chmod 600` + `export GIT_SSH_COMMAND="ssh -i ~/.ssh/deploy_key -o StrictHostKeyChecking=accept-new"`，再跑 `hexo generate -d`。`webfactory/ssh-agent@v0` 这个 tag 不存在（该 action 用具体版本号），别用。
4. **workflow 文件改了不自动跑**：`on.push.paths` 必须包含 `.github/workflows/circle.yml` 自身，否则改 workflow 不会触发。CI 装的 pnpm 是 latest（v12.14.0），注意红线 1。
5. **PAT 用途**：zuige 给的 PAT（ghp_...）本次用于创建 Actions Secret + 查 workflow 状态（API）。红线：私钥/密钥绝不入库、绝不进 git 跟踪文件；PAT 过期（约 2027-01-10）向 zuige 重取。

### 本轮新增红线 / 经验
1. **`.gitignore` 不支持行内注释**：原 `source/circle/circle.json        # 注释` 整行被当成 pattern，导致生成文件没被忽略、差点误提交。规则：`.gitignore` 的注释必须独占一行，pattern 行不带 `#`。
2. **CSS Grid 优先于 Bootstrap `.row` 浮动**：在 `.row` 容器内放自渲染卡片块时，直接给该容器 `display:grid` 覆盖，避免浮动/高度塌陷重叠。
3. **归档持久化的关键**：RSS 只暴露近期文章，历史只能从"现在"起累积；必须落盘 `circle-archive.json` 并让 workflow 写回 main，否则每次 Actions 运行都是全新空归档。
4. `circle-archive.json` 入库（不进 .gitignore）；`source/circle/circle.json` 生成物忽略。提交时显式 `git add` 特性文件，别 `git add -A`（会带上 `.workbuddy/` 记忆与 stray 文件如 cloud-sea-sandbox.html）。
5. PortableGit 实际版本是 1.3.0（非 1.2.0），curl 路径要随版本号走；Windows curl 访问 GitHub 加 `--ssl-no-revoke`。
