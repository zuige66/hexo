## 首页左侧栏粘性吸顶（sticky sidebar，已上线 deploy 3887c35 / commit 4a20887）

- 需求（zuige 语音转文字，原话含糊）：首页左栏（个人卡片/统计/热力图/分类/标签/最近文章）下滑时会跟着滚走，希望「滚到分类的时候就固定住，不再往下滑，只有右边往下滑，左边不动」。并问这个效果叫什么。
- **术语**：叫**粘性侧边栏（sticky sidebar）**，也叫「侧边栏吸顶 / 跟随固定」；实现靠 CSS **`position: sticky`**（区别于 `position: fixed`：fixed 一开始就钉死，sticky 是滚到位置才吸住）。
- 首页布局（自定义）：`themes/fluid/layout/index.ejs` 里 `.home-with-sidebar` 是 CSS Grid `280px minmax(0,1fr)` + `align-items:start`；左 `.home-sidebar`，右 `.home-post-list`。改前 `.home-sidebar` 是 `position: static`，所以整条滚没。
- 两个可选方案，zuige 选了 **A「滚到分类再锁定」**（另一方案是整体一滚就吸顶 + 内部滚动条）。
- 实现：
  1. `index.ejs`：给「分类」`<section>` 加 `home-sticky-anchor` 类作锚点（注意「分类/标签/最近文章」三个 section 都是 `home-side-card home-list-card`，要靠 h3 文案区分）。
  2. 新增 `source/js/home-sidebar-sticky.js`：动态算 `top`。
     - 公式：`top = navH + TOP_GAP - d`，`d` = 锚点相对侧栏顶部距离。`d > navH+GAP` 时 top 为负 → 侧栏先跟滚一段再锁住，正好停在「分类」对准导航栏下方。
     - 兜底：若 `top > vh - h - BOTTOM_GAP`（屏幕放不下「分类以下」内容）→ 退化为 `top = nav` 整体吸顶 + `maxHeight` + `overflow-y:auto`，保证「最近文章」可达。
     - 先清空内联样式再测量（避免上一次的 maxHeight 污染 offsetHeight）。
     - 监听 `resize`（防抖 120ms）、`window load`、`softnav:loaded`（软导航换页后侧栏是新建的）。
  3. `source/css/home-sidebar.css`：`.home-sidebar` → `position: sticky; top: 76px`（无 JS 兜底）。
  4. `_config.fluid.yml`：`custom_js` 加 `/js/home-sidebar-sticky.js?v=1`；`home-sidebar.css` 版本 `?v=3` → `?v=4`。
  5. `hexo-customize-guide.md` 新增「十五、首页侧栏吸顶」章节（含如何改锁定点/间距）。
- 验证：build 74 文件；线上首页确认 `home-sidebar-sticky.js?v=1`、`home-list-card home-sticky-anchor`、`home-sidebar.css?v=4` 均就位；Pages 构建 built。

### 本轮红线 / 经验
1. **所有自定义 JS 引用必须带 `?v=N`，改 JS 必须 bump**（延续 2026-10-17 的坑）。CSS 与 JS 的缓存互相独立，只 bump 一个不够。
2. **JS 里改 breakpoint 必须与 CSS 同步**：脚本的 `MOBILE_MAX = 767` 对应 `home-sidebar.css` 的 `@media (max-width: 767px)`，改一处必须改另一处。
3. **sticky 失效第一排查点**：祖先链上任何 `overflow: hidden/auto`（本项目只有 `body.mobile-menu-open` 一处，无影响）；其次父容器要 `align-items: start`（已是）。
4. **测量前先清内联样式**，否则上轮写入的 `max-height` 会让 `offsetHeight` 读到被约束后的值，迭代计算发散。
5. 软导航（`soft-nav.js`）会重建 `#board`，任何针对首页元素的初始化脚本都要监听 `document` 的 `softnav:loaded` 事件重跑。
6. `hexo deploy` 推完 gh-pages ≠ 线上生效，Pages 构建约 1~3 分钟；校验用随机查询参数绕 CDN（10 分钟缓存）。

## 修复：展开全部标签后简介/统计「消失」（commit 5df6b0e，?v=2）

- 现象：展开「展开全部标签」→ 侧栏比屏幕高 → 页面滚回顶部后，侧栏从标签列表中间开始，简介/统计/热力图全不见（zuige 截图）。
- 根因：v1 兜底逻辑走「整体吸顶 top=nav + maxHeight/overflow-y 内部滚动」。在侧栏上滚滚轮滚的是**侧栏内部**，顶部卡片被卷进内部视口上方；内部滚动位置**残留**，页面滚回顶部后侧栏仍从中间内容开始——看起来像卡片消失。
- 修复：**彻底移除内部滚动条**。装不下「分类以下」内容时改为锁定时**侧栏底部对齐屏幕底部**（`top = vh - BOTTOM_GAP - h`），刚展开的标签/最近文章可见；回滚到顶侧栏恢复原位。`ResizeObserver` 监听侧栏高度变化自动重算（展开/收起标签即触发）。
- 红线：**sticky 侧栏绝不用 maxHeight+overflow 内部滚动兜底**——内部滚动位置残留 = 顶部内容「隐形」。装不下就底部对齐。
- 实现细节：ResizeObserver 观察目标**必须去重**（disconnect 后重新 observe 同一元素会触发初始回调 → schedule → apply → 再 observe → 死循环）；apply 前先清内联样式再测 offsetHeight。

## 重构：sticky 锁定点在 iPad 漂移 → 改为纯 CSS 容器吸附（commit 待提交，deploy 待上线）

- 现象（zuige 截图 + 原话）：改完「部分标签」后，左栏锁定点不可靠——iPad 上有时卡在「杂记」、有时卡在「技术」，正常应卡在「分类」两字处；上下滑还会乱跳。
- 根因：**JS 动态计算的负 top sticky 在 iPad Safari 上不可靠**。iPad 地址栏/工具栏随滚动收展会改变 `innerHeight` 与视觉位置，脚本的 `top = nav - d` 反复重算 → 锁定基准漂移，于是偶尔锁在别的卡片上。
- 修复思路：彻底弃用 JS 算 top，改用**纯 CSS 容器 sticky + 常数 top**。
  - `index.ejs`：把「分类 + 部分标签 + 最近文章」三个 `<section>` 整体包进 `<div class="home-side-sticky">`（去掉无用的 `home-sticky-anchor`）。上半栏（头像/统计/热力图）留在正常流，自然滚走。
  - `home-sidebar.css`：`.home-sidebar` 去掉 `position: sticky`；新增 `.home-side-sticky { position: sticky; top: 76px; max-height: calc(100vh - 76px - 16px); overflow-y: auto; }`。`top` 是常数，不依赖 JS，iPad 上不会漂移；内容过高只在本容器内滚动，不影响上半栏。版本 ?v=5→?v=6。
  - **删除 `source/js/home-sidebar-sticky.js`**（`git rm`），并从 `_config.fluid.yml` 的 `custom_js` 移除引用。软导航换页无需再重跑吸附脚本（纯 CSS 自动生效）。
- 验证：本地 `hexo g` 71 文件通过；`public/index.html` 含 `.home-side-sticky`、不含 `home-sidebar-sticky`、CSS 引用 `?v=6`；已 `hexo deploy` 推 gh-pages（commit bcd4933）。
- 红线 / 经验：
  1. **移动端（尤其 iPad Safari）不要用 JS 计算负 top 的 sticky 跟随**——工具栏收展会让测量值抖动、锁定点漂移。标准可靠的「滚一段再锁」靠 `position: sticky` + 常数 `top` 在**容器**上实现（上半部分留在正常流）。
  2. **容器 sticky 模式**：要「先滚走一部分再锁」，就把下半部分包进一个 sticky 容器，上半部分不包；容器 top 是常数即可，无需 JS。
  3. 容器 sticky 若内容高于视口，用 `max-height + overflow-y:auto` 兜底（仅容器内滚，不影响已滚走的上半栏）；与旧「整体吸顶+内部滚动」不同——旧法的坑是上半栏被卷进内部视口，本法的上半栏在容器外、正常流，安全。
  4. 删除自定义 JS 别忘了同时从 `_config.fluid.yml` `custom_js` 摘掉引用，否则部署后 404 拖累加载。

## 二次返工：容器吸顶「完全不吸顶」→ 父容器必须拉满 Grid 行高（deploy c673a10 / commit 待提交）

- 现象（zuige 原话）：上轮改成容器吸附后，「完全就是不会卡住了，一直往下」——左栏整条跟着滚走，不吸顶。
- 根因：**sticky 子元素只能在「父容器范围内」钉住**。上轮把 `.home-with-sidebar` 设了 `align-items: start`，让 `.home-sidebar`（父）只有「自身内容高」（约 1300px）；`.home-side-sticky` 钉住一小段（刚够上半栏滚走）后父级底就到，于是整条左栏滚走 → 看起来完全不吸顶。而旧版是「整个 `.home-sidebar` 吸顶」，其父是 Grid 行（=右栏那么高），所以能一路钉住。
- 修复：给 `.home-sidebar` 加 `align-self: stretch`，拉满 Grid 行高（实测 2211px，与右栏等高），下半块 `.home-side-sticky` 即可在整页高度内钉住。CSS 版本 ?v=6→?v=7。
- **真机/无头验证**：用 Python playwright 无头 Chromium 加载线上首页，滚动 1400/1900/2300px 时 `.home-side-sticky` 视口 top 均稳定 = 76px、`.home-profile-card` top 为 -452/-952/-1352（上半栏已滚走）→ 确认吸顶生效。判定脚本首次报 False 是误把「scroll=800 还没滚到分类」的预钉点也算进去，非真 bug。
- 红线 / 经验：
  1. **sticky 子元素的钉住范围 = 父容器高度 − 自身高度 − top**。想让某块「钉住陪右栏滚」，它的父容器必须足够高（至少≈右栏高度）。Grid 场景下父是 Grid item，务必确认它被拉伸（`align-items: stretch` 或 `align-self: stretch`），别用 `align-items: start` 把它压成内容高。
  2. **改完 sticky 别只靠推理**——前两轮都靠推理翻车（漂移、不吸顶）。用 playwright 无头浏览器实测滚动后元素的 `getBoundingClientRect().top` 是否稳定在某值，比肉眼/推理可靠。脚本临时放 `tools/_sticky_check.py`，验证完即删。
  3. 判定 sticky 是否生效时，滚动量要落在「已越过上半栏、且未超出父容器底」的区间；滚太深（父容器到底后）元素自然滚走，不是 bug。
